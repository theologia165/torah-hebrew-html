# Work stage｜Image handoff

JSON2確定後、Notion完成を待たずに当日画像を作る。入力は次の三層だけであり、過去ページ・過去画像・失敗画像・過去gen_idを使わない。

1. `ver3/config/image-master.json`
2. `ver3/config/parasha-image/index.json`から日本語パラシャー名を完全一致して取得する当日profile
3. 当該RUNのJSON2から一時的に組むCURRENT RUN IMAGE PACKAGE

## 右側場面の画角・ピント・光

GLOBAL IMAGE MASTERの`right_scene.photographic_direction`を毎回の画像生成プロンプトへ反映する。文字部分と場面部分は役割を分けるが、従来どおり文字入りの一枚を生成する。

CURRENT RUN IMAGE PACKAGEには、当日本文と主題に基づき、次の撮影意図を短く具体化する。一時的なプロンプト要素とし、別の恒久ファイルや監査JSONを増やさない。

- **主対象と瞬間**：誰のどんな表情・動作・関係、またはどの物・風景へ視線を導くか。
- **見る人の立場と画角**：見る人を物語のどこに立たせるか（同席者、対話を聞く者、出発を見送る者など）を先に決め、その立場からカメラの高さ・距離・方向を選ぶ。正面から全要素を均等に見せる構図を初期値にせず、当日の中心的な行為・関係・緊張を伝える。対話なら肩越しや斜め、重要な動作なら手元への寄り、共同体の移動なら引きなどを候補とする。正面が主題に合えば意図して用い、斜め45度や低い位置へ一律に固定しない。
- **視線の流れ**：画角と絞りを一緒に設計し、既存の食卓の辺・手や道具・人物の視線などで主対象へ導く。カメラの具体的な位置と、見る人の視線がたどる順序を短く記す。傾いた水平線や強い広角歪みを工夫の代わりにしない。
- **ピントと奥行き**：何を鮮明にし、何をどの距離でぼかすか。適する場面では「ぼけた前景→鮮明な主対象→柔らかな遠景」で立体感を出す。本文にない物や人物をぼけ用に追加しない。関係する人物の顔・手・行為は一緒に読める被写界深度を確保し、焦点距離や絞り値を毎回固定しない。
- **光と質感**：当日場面とprofileに沿って光源の方向と陰影を選び、必要に応じて逆光・反射光を使う。自然な肌・布の質感と絵画的な温かさを残す。毎回同じ夕日や集合ポーズへ固定しない。

写真表現は右側場面だけに適用する。左側文字にはぼけ・被写界深度・光のにじみをかけず、必須文字・本文への忠実さを優先する。過去画像の構図を複製せず、既存profileの色調・素材・歴史的世界と共存させる。ぼけの強さや三層構図自体を必須条件にしない。


## 人体だけの独立した拡大検品（構図評価の前に必須）

生成指示に「正しい人体」と書いたことや、全体表示で自然に見えることを合格証拠にしない。主要人物を一人ずつ切り出し、画像ビューアで頭部・上肢・下肢・接触部を十分な大きさに拡大して実画像を確認する。検品用の切り出しは一時的な観察資料であり、生成・編集の入力には使わず、GitHubへ画像を保存しない。

1. 人物ごとに頭・胴体・左右の腕・左右の脚の対応を追い、肩→肘→手首→手、股関節→膝→足首→足の連続と関節の向きを確認する。腕や指の本数だけで判定しない。
2. 左右それぞれの手について、手のひら／甲、親指の付く側、残りの指の付け根・本数・曲がり方を確認し、左腕に右手のような手が付いていないか確かめる。指・手・足の融合、分岐、重複、極端な長さや捻れも調べる。
3. 荷物・道具・衣服・他者と重なる箇所は、誰の手足かを特定し、握る／支える接触位置と重さに対する姿勢が成立するか確認する。自然な遮蔽は認めるが、布やぼけを理由に重要な手の不明点を見過ごさない。確認不能はPASSにせずUNCERTAINとして不採用とする。
4. 背景人物も全体で走査し、読み取れる範囲の重複・分離した手足・融合を確認する。人物がいない画像は、その事実を根拠にNOT_APPLICABLEとする。
5. 人体の確認を終えてから別の観点で文字・本文忠実性・画角・焦点・光を評価する。人体のFAIL／UNCERTAINを美しい構図で相殺しない。画像生成は合計最大3回、失敗画像は参照せずfresh生成する。

合格時は既存のcover-ready.jsonのqa欄に、拡大して確認した人物・部位、左右の手と接触の判断を具体的に記す。「人体は自然」「腕が二本」だけで済ませず、実際に拡大表示を見ていない場合は確認済みと記さない。専用の監査JSONは増やさない。人物や部位を特定できないまま上限に達した画像は配信せず、既存の未完了報告手順を使う。

## 生成・確認・受け渡し

1200×630のfresh画像を生成し、従来の10項目（NNN、パラシャー名、アリヤー、聖書箇所、本文由来主題句、必要時の補助コピー、誤字、別回混入、本文場面、寸法）を目視確認する。加えて、見る人の立場と選んだカメラ位置が実際の構図に表れ、本文の中心的な行為や緊張が伝わるか、主題へ視線が向くか、距離に応じた自然な鮮明さ・ぼけか、重要な表情・手・人物関係と左側文字を損なっていないか、縮小表示でも主題と文字が伝わるかを確認する。写真表現の評価は場面への適合性で判断し、強いぼけがないことだけで不合格にしない。不合格画像は参照・編集せず、最大3回fresh generationする。

PASS画像だけを`cover-upload.json`の短時間PUT URLへJPEGバイナリとして直接送る。画像バイナリをGitHubやWorkの文字コンテキストへ入れない。R2で1200×630 JPEGと取得可能性を確認し、当該RUNの`cover-ready.json`だけをコミットしてActionsを再起動する。画像監査専用JSONや恒久的なCURRENT RUN IMAGE PACKAGEは作成しない。
