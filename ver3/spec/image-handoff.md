# Work stage｜Image handoff

JSON2確定後、Notion完成を待たずに当日画像を作る。入力は次の三層だけであり、過去ページ・過去画像・失敗画像・過去gen_idを使わない。

1. `ver3/config/image-master.json`
2. `ver3/config/parasha-image/index.json`から日本語パラシャー名を完全一致して取得する当日profile
3. 当該RUNのJSON2から一時的に組むCURRENT RUN IMAGE PACKAGE

## 制作と検品の順序：構図を先に決める

順序は **本文とキーワード→主題と三案比較→画角・距離・レンズ・絞り・光の決定→fresh生成→主題・構図の実現確認→描写範囲に即した人体拡大検品→全体・縮小表示で最終確認** とする。人体検品のしやすさを、構図選択の先決条件にしない。全身像、横並び、直立、足の露出を検品のために要求しない。

構図の実現確認では、意図を読み直す前に場面だけを見て行為・関係を記述し、その後で意図と照合する。狙った立場・画角・主題の強調が成立していない場合は、人体や文字が整っていても採用しない。人体検品後にも全体・縮小へ戻り、同じ構図で主題と人体が共に成立することを再確認する。

胸像、肩越し、手元への寄りなど、主題から選んだフレーミングを認める。画面外の脚を検証するために全身像へ変えない。画面内の人体、衣服・他者による遮蔽、画面端での切れ方を評価し、範囲外は「構図上の画面外・未観察」と記す。後から発見した不自然な手足を切り落としたりぼかしたりして合格にすることとは区別する。

## アリヤー固有のキーワードから主題を選び、完成画像を判定する

画角や人物配置を決める前に、当該RUNのJSON2の対象全節を読み、アリヤー固有の重要語・重要句をWork自身が列挙する。summaryや表題だけから選ばない。ここでいうキーワードは名詞だけでなく、行為・関係・対比・転換を表す短句を含む。利用者の助言を待たずに抽出し、助言がある場合もその語が本文の中で何を担うかを照合する。過去RUN・過去画像を抽出元にせず、画像工程の三層入力とhandoffの読込範囲を守る。

### 1. 根拠を伴う候補の列挙

該当する観点から、重複しない少数の候補を列挙する。件数や全分類の穴埋めを目的にしない。

- 語りの主体・行為の受け手：個人、民・家族などの共同体、指導者、対立者。単数／集合の違いも読む。
- 中心的な動詞と対象：誰が、誰に／何に、何をするのか。
- 関係・対比・緊張：導く／追い戻す、与える／奪う、近さ／迂回など、当日本文にある結び付き。
- 場面の転換、反復、強調、制約：行為や道筋を変える命令、昼夜、まだ起きていない出来事など。
- 物・場所・しるし：名称だけでなく、それが人々の行為や関係の中で果たす役割。

一時的な比較表は「語・短句｜根拠節｜本文中の役割・結び付く相手や行為｜主題候補／補助／今回描かない、とする理由」とする。出現回数の多さ、描きやすさ、固有名であることだけで優先しない。「民」「旅」「信仰」のように他の日にも通用する語は、そのアリヤーの行為・関係に結び付けて初めて候補とする。本文から確かめられない抽象語や、本文にない象徴・出来事は候補に加えない。

### 2. 語の一覧を、一枚で伝える関係へ絞る

候補を比較し、「誰／何が、誰／何と、どのような行為・関係・緊張にある瞬間か」を主題として一文にする。主題を支える語・短句を選び、残りを補助または今回描かないものとして整理する。全キーワード・全場面を均等に並べる必要はない。

この時点で主対象を個人・共同体・関係・行為・物・風景のどれとして扱うか判断する。本文の主役が共同体や関係である場合、描きやすい一人の肖像へ縮めて中心を失っていないかを検討する。一人を通して共同体を表す構図も認めるが、他者や進路との関係が画面から読めることが条件となる。毎回「民」や集合構図へ固定しない。

例えば出13:17–14:8では、「民（13:17–18、14:5–8）」「導く／回り道（13:17–18）」「ヨセフの骨と顧みの約束（13:19）」「前を行く雲・火（13:21–22）」「解放を惜しみ追うファラオ（14:5–8）」等を比較できる。「民」は集合人数の指定ではなく、神に導かれ、他方で追跡される共同体という関係の候補である。「導かれる民」を主題に選ぶなら、民・進路・先立つしるしの関係を可視化し、骨や戦車も一枚へ詰め込むことは求めない。これは方法の説明例であり、以後のRUNの固定キーワード集や研究入力ではない。

### 3. 既存の三案比較・撮影意図へ受け渡す

選んだ主題と支える語の関係を、既存の三つの画角案の比較軸にする。各案について、何が強く伝わり、何が失われるかを検討し、一案を選ぶ。キーワードごとの画像生成や新たな三枚生成は追加しない。

生成プロンプトでは、語を並べるだけでなく、その関係を示す人物の方向・視線・距離・進路・接触・配置・光・鮮明さを具体化する。キーワードを左側文字へすべて書き込んで伝達の不足を補わない。主題からレンズと画角を選び、先に決めた格好よい構図へ本文を当てはめない。

### 4. 主題伝達を独立して検品する

生成後、人体検品へ入る前に、撮影意図や候補表を読み直さず完成画像の場面部分だけを見て「誰／何が、何をし、どんな関係にあるように見えるか」を短く言語化する。次に、必須文字を含む全体を縮小表示し、主題と文字の読み取りを確認する。最後に、選んだ主題・重要語・関係と照合する。

- 主題の主体や受け手を読み取れるか。共同体や関係を選んだのに、孤立した一人の見栄えだけが中心になっていないか。
- 選んだ行為・関係が、視線・方向・配置・距離・光から読めるか。関連する物がそれぞれ存在するだけになっていないか。
- 本文が支える範囲の場面・瞬間か。後続の出来事や別の物語、単なる風景・装飾物として強く誤読させないか。
- 縮小後も中心が保たれ、背景の明るさ・精細さ・主題外の要素が競合していないか。

場面だけで当日アリヤーや章節を正確に言い当てることまでは求めない。左側文字は識別・文脈の補助に使う。一方、「人体が正しい」「本文に出る物がある」「題名を読めば意味が分かる」ことは、選んだ関係が場面で伝わる証拠にはしない。

本文忠実性、人体、主題伝達、文字の可読性はそれぞれ独立してPASSを要する。主題の関係を説明文で補わなければ読めない場合や、重要な読み取りが不確かな場合は主題伝達をFAIL／UNCERTAINとし、他の合格で相殺しない。既存の最大3回の範囲内でfresh生成し直し、上限で合格しない画像は未完了報告へ進める。

候補表と主題の選択は一時的なCURRENT RUN IMAGE PACKAGEの中で行い、専用ファイルや恒久的な監査JSONを増やさない。採用時だけ既存cover-ready.jsonのqa欄へ、選んだ主題と根拠節、画像だけから実際に読み取った行為・関係、縮小表示と照合の判断を短く残す。Workの意味判断を、Actionsの機械PASSに代行させない。

## 右側場面の画角・ピント・光

GLOBAL IMAGE MASTERの`right_scene.photographic_direction`を毎回の画像生成プロンプトへ反映する。文字部分と場面部分は役割を分けるが、従来どおり文字入りの一枚を生成する。

CURRENT RUN IMAGE PACKAGEには、上記のキーワード比較から選んだ主題と重要な関係に基づき、次の撮影意図を短く具体化する。一時的なプロンプト要素とし、別の恒久ファイルや監査JSONを増やさない。

- **主対象と瞬間**：誰のどんな表情・動作・関係、またはどの物・風景へ視線を導くか。
- **見る人の立場と画角**：見る人を物語のどこに立たせるか（同席者、対話を聞く者、出発を見送る者など）を先に決め、その立場からカメラの高さ・距離・方向を選ぶ。正面から全要素を均等に見せる構図を初期値にせず、当日の中心的な行為・関係・緊張を伝える。対話なら肩越しや斜め、重要な動作なら手元への寄り、共同体の移動なら引きなどを候補とする。正面が主題に合えば意図して用い、斜め45度や低い位置へ一律に固定しない。
- **視線の流れ**：画角と絞りを一緒に設計し、既存の食卓の辺・手や道具・人物の視線などで主対象へ導く。カメラの具体的な位置と、見る人の視線がたどる順序を短く記す。傾いた水平線や強い広角歪みを工夫の代わりにしない。
- **ピントと奥行き**：何を鮮明にし、何をどの距離でぼかすか。適する場面では「ぼけた前景→鮮明な主対象→柔らかな遠景」で立体感を出す。本文にない物や人物をぼけ用に追加しない。関係する人物の顔・手・行為は一緒に読める被写界深度を確保し、焦点距離や絞り値を毎回固定しない。
- **光と質感**：当日場面とprofileに沿って光源の方向と陰影を選び、必要に応じて逆光・反射光を使う。自然な肌・布の質感と絵画的な温かさを残す。毎回同じ夕日や集合ポーズへ固定しない。

写真表現は右側場面だけに適用する。左側文字にはぼけ・被写界深度・光のにじみをかけず、必須文字・本文への忠実さを優先する。過去画像の構図を複製せず、既存profileの色調・素材・歴史的世界と共存させる。ぼけの強さや三層構図自体を必須条件にしない。


## 主題を大胆に強調する演出

各アリヤーで伝える行為・関係・緊張を一つ定め、全景を均等に詳しく描くことを完成度の基準にしない。画角・高さ・レンズ・F値相当・被写体距離・人物配置・光の配分を一体として選び、主題に必要な部分へ鮮明さと明るさを大胆に集中させる。重要でない背景は、思い切ったぼけ・暗部・画面外への省略を選択できる。数値だけでなく「何が鮮明で何が読めなくなるか」を具体的に指示する。

三案比較では、見る人と主対象の距離や背景との前後関係が異なる案を検討する。広角寄りで近づくことで動き・奥行きを強める案、遠くから望遠で捉えて人物と背景の見かけの距離を縮める案など、当日の主題への効果と失われる情報を比べる。焦点距離だけで遠近感が変わると説明せず、カメラ位置と被写体距離も指定する。

低位置・望遠・開放絞り・逆光・朝日・暗い周囲を毎回の定型にしない。今回の104から継承するのは「中心を強くし、周辺を描き込みすぎない判断」であり、登場人物・構図・数値ではない。関係を示す相手の表情、重要な動作、本文忠実性、人体検品、文字可読性は保つ。完成画像では、狙った強調が縮小表示でも一目で伝わるかを評価し、均一な明るさ・鮮明さや装飾的な美しさだけで合格にしない。

荒野や旅の場面では、遠くから望遠で隊列・山並み・地平線の重なりを凝縮する表現や、広大な土地の中の人物を切り取る表現を有力な候補にする。歩みの重さ・孤独・共同体の連なりのうち当日本文が支える主題から選び、空間の広がりを伝える広角の効果とも比較する。望遠や大きな朝日を旅の定型にせず、レンズ演出のために本文にない場面を加えない。

## 選んだ構図に即した人体判定と独立した拡大検品（構図の実現確認後）

人体のPASSは、描かれた範囲の局所が自然であり、画像全体で人物の姿勢・比率・遮蔽が整合することを必要とする。「全体表示」は完成画像全体を見ることであり、必ず全身を描くという意味ではない。

検品順序は **完成画像全体で描写範囲・比率・姿勢を判定→主要人物の見えている部位と重要な接触部を実際に拡大表示→完成画像全体・縮小表示へ戻って人体と主題を再判定** とする。局所の拡大だけで合格を出さない。人物がいない画像はその根拠を記してNOT_APPLICABLEとする。

| 判定対象 | 構図に即したPASS条件 |
|---|---|
| 身体の連続 | 画面内の頭・首・肩・胴・腕・手などが同じ人物へ無理なく連続する。骨盤や脚が描かれる構図では、左右の股関節→太腿→膝→下腿→足首→足も描写範囲に応じて追う |
| 比率と姿勢 | 見えている頭・胴・骨盤・四肢の比率と関節位置が整合する。全身像では説明できない胴長・短足・身長の圧縮がない。胸像の画面外の下肢を不合格理由にしない |
| 左右の脚と歩行 | 脚・足が描かれる場合、支持と動き、歩幅・膝・足の方向、左右の前後関係が一致する。脚を描かない構図では未観察とし、検品のためだけに足を追加しない |
| 重心と接触 | 描写範囲から判断できる胴の傾き、荷物・道具・他者との接触と荷重が成立する。接地が画面内にある場合は足裏と地面の関係も確認する |
| 遠近法・短縮・遮蔽・画面端 | 見える形、カメラ方向、身体の向き、衣服・他者による遮蔽と画面端の切れ方が一貫する。望遠・低位置の指定だけで不自然さを正当化しない |

固定の頭身や一つの理想体型を要求しない。自然な重なり・衣服の遮蔽・構図上の画面外は認め、直接見た部位と、輪郭から整合を判断した部位と、未観察の部位を区別する。画面外や自然な遮蔽だけを理由にUNCERTAINとしない。一方、画面内の身体の帰属・左右・関節や、主題に不可欠な手・接触に矛盾する複数の解釈が残る場合はUNCERTAINとして不採用とする。見つかった不良を追加のぼけ・切断で隠して合格にしない。

1. 全体判定後、主要人物を一人ずつ一時的に切り出して実際に拡大表示し、見えている関節と重要な接触を追う。肩→肘→手首→手、脚が描かれる場合は骨盤から足までの連続を確認する。
2. 見える左右の手について手のひら／甲、親指の側、指の付け根・本数・曲がりを確認し、反転・融合・分岐・重複・極端な長さや捻れを調べる。見えない指を数えたとは記さない。
3. 荷物・道具・衣服・他者との重なりは、見える範囲から誰の手足か、接触と荷重が成立するかを確認する。主題に必要な可視部位の不確かさをPASSにしない。
4. 背景人物も走査し、読み取れる重複・分離・融合を確認する。意図した距離により読めない細部は認定しない。
5. 完成画像全体と縮小表示へ戻り、局所では見落とす比率・姿勢・重心・関係の矛盾がないか再確認し、主題・構図・人体・文字を最終判定する。

全体判定・局所拡大判定・全体再判定の対象範囲にFAIL／UNCERTAINが残れば不採用とする。人体と構図は独立した合格条件であり、互いの不合格を相殺しない。最大3回のfresh生成に含め、不合格画像・過去画像を参照／編集入力にしない。

合格時だけ既存cover-ready.jsonのqa欄へ、先に選んだ構図の描写範囲、実際に拡大確認した人物・部位と左右／接触、全体の比率・姿勢・短縮・遮蔽、適用できる脚／接地の判断、構図上の画面外／未観察、全体・縮小の再判定を記す。「人体は自然」「腕が二本」だけを合格証拠にしない。専用監査JSONや恒久的な検品画像は増やさない。上限で合格しない画像は配信せず未完了報告へ進む。

## 生成・確認・受け渡し

1200×630のfresh画像を生成し、従来の10項目（NNN、パラシャー名、アリヤー、聖書箇所、本文由来主題句、必要時の補助コピー、誤字、別回混入、本文場面、寸法）を目視確認する。上記の独立した主題伝達の検品を実施し、見る人の立場と選んだカメラ位置が実際の構図に表れ、本文の中心的な行為や緊張が伝わるか、主題へ視線が向くか、距離に応じた自然な鮮明さ・ぼけか、重要な表情・手・人物関係と左側文字を損なっていないか、縮小表示でも主題と文字が伝わるかを確認する。写真表現の評価は場面への適合性で判断し、強いぼけがないことだけで不合格にしない。不合格画像は参照・編集せず、最大3回fresh generationする。

PASS画像だけを`cover-upload.json`の短時間PUT URLへJPEGバイナリとして直接送る。画像バイナリをGitHubやWorkの文字コンテキストへ入れない。R2で1200×630 JPEGと取得可能性を確認し、当該RUNの`cover-ready.json`だけをコミットしてActionsを再起動する。画像監査専用JSONや恒久的なCURRENT RUN IMAGE PACKAGEは作成しない。
