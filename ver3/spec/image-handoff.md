# Work stage｜Image handoff

JSON2確定後、Notion完成を待たずに当日画像を作る。入力は次の三層だけであり、過去ページ・過去画像・失敗画像・過去gen_idを使わない。

1. `ver3/config/image-master.json`
2. `ver3/config/parasha-image/index.json`から日本語パラシャー名を完全一致して取得する当日profile
3. 当該RUNのJSON2から一時的に組むCURRENT RUN IMAGE PACKAGE

## 右側場面の画角・ピント・光

GLOBAL IMAGE MASTERの`right_scene.photographic_direction`を毎回の画像生成プロンプトへ反映する。文字部分と場面部分は役割を分けるが、従来どおり文字入りの一枚を生成する。

CURRENT RUN IMAGE PACKAGEには、当日本文と主題に基づき、次の撮影意図を短く具体化する。一時的なプロンプト要素とし、別の恒久ファイルや監査JSONを増やさない。

- **主対象と瞬間**：誰のどんな表情・動作・関係、またはどの物・風景へ視線を導くか。
- **見る人の立場と画角**：見る人を物語のどこに立たせるか（同席者、対話を聞く者、出発を見送る者など）を先に決め、その立場からカメラの高さ・距離・方向を選ぶ。正面から全要素を均等に見せる構図を初期値にせず、当日の中心的な行為・関係・緊張を伝える。対話なら肩越しや斜め、重要な動作なら手元への寄り、共同体の移動なら引きなどを候補とする。正面が主題に合えば意図して用い、斜め45度や低い位置へ一律に固定しない。
- **視線の流れ**：画角と絞りを一緒に設計し、既存の食卓の辺・手や道具・人物の視線などで主対象へ導く。カメラの具体的な位置と、見る人の視線がたどる順序を短く記す。傾いた水平線や強い広角歪みを工夫の代わりにしない。
- **ピントと奥行き**：何を鮮明にし、何をどの距離でぼかすか。適する場面では「ぼけた前景→鮮明な主対象→柔らかな遠景」で立体感を出す。本文にない物や人物をぼけ用に追加しない。関係する人物の顔・手・行為は一緒に読める被写界深度を確保し、焦点距離や絞り値を毎回固定しない。
- **光と質感**：当日場面とprofileに沿って光源の方向と陰影を選び、必要に応じて逆光・反射光を使う。自然な肌・布の質感と絵画的な温かさを残す。毎回同じ夕日や集合ポーズへ固定しない。

写真表現は右側場面だけに適用する。左側文字にはぼけ・被写界深度・光のにじみをかけず、必須文字・本文への忠実さを優先する。過去画像の構図を複製せず、既存profileの色調・素材・歴史的世界と共存させる。ぼけの強さや三層構図自体を必須条件にしない。


## 主題を大胆に強調する演出

各アリヤーで伝える行為・関係・緊張を一つ定め、全景を均等に詳しく描くことを完成度の基準にしない。画角・高さ・レンズ・F値相当・被写体距離・人物配置・光の配分を一体として選び、主題に必要な部分へ鮮明さと明るさを大胆に集中させる。重要でない背景は、思い切ったぼけ・暗部・画面外への省略を選択できる。数値だけでなく「何が鮮明で何が読めなくなるか」を具体的に指示する。

三案比較では、見る人と主対象の距離や背景との前後関係が異なる案を検討する。広角寄りで近づくことで動き・奥行きを強める案、遠くから望遠で捉えて人物と背景の見かけの距離を縮める案など、当日の主題への効果と失われる情報を比べる。焦点距離だけで遠近感が変わると説明せず、カメラ位置と被写体距離も指定する。

低位置・望遠・開放絞り・逆光・朝日・暗い周囲を毎回の定型にしない。今回の104から継承するのは「中心を強くし、周辺を描き込みすぎない判断」であり、登場人物・構図・数値ではない。関係を示す相手の表情、重要な動作、本文忠実性、人体検品、文字可読性は保つ。完成画像では、狙った強調が縮小表示でも一目で伝わるかを評価し、均一な明るさ・鮮明さや装飾的な美しさだけで合格にしない。

荒野や旅の場面では、遠くから望遠で隊列・山並み・地平線の重なりを凝縮する表現や、広大な土地の中の人物を切り取る表現を有力な候補にする。歩みの重さ・孤独・共同体の連なりのうち当日本文が支える主題から選び、空間の広がりを伝える広角の効果とも比較する。望遠や大きな朝日を旅の定型にせず、レンズ演出のために本文にない場面を加えない。

## 人体の全身判定と独立した拡大検品（構図評価の前に必須）

人体のPASSは「局所が自然」に加えて「全身として姿勢が成立する」ことを必要とする。従来の関節確認を実施したつもりで合格にせず、全身判定を独立した合否条件として実画像で確かめる。

検品順序は **全身表示で骨格・比率・重心を判定 → 人物ごとの拡大表示で関節・手指・接触を判定 → 全身表示と縮小表示へ戻って再判定** とする。局所の拡大だけで合格を出さない。人物がいない画像はその事実を根拠にNOT_APPLICABLEとする。

| 全身の判定対象 | PASSの条件 |
|---|---|
| 骨盤から足までの連続 | 左右それぞれの股関節→太腿→膝→下腿→足首→足が、同じ一本の脚として無理なく追える |
| 全身の比率 | 頭・胴体・骨盤・脚の長さと関節位置が整合し、説明できない胴長・短足・身長の圧縮がない |
| 左右の脚と歩行 | 支持脚と動いている脚が明確で、歩幅・膝の曲がり・足の方向・左右の前後関係が一致する。静止姿勢では両脚の支持関係を判定する |
| 重心と接地 | 身体と荷物の重さを接地した足で支えられ、胴体の傾き・荷重移動・足裏の向きに矛盾がない |
| 遠近法と短縮 | 短く見える部位をカメラ位置・身体の向き・遮蔽から説明でき、他の部位と一貫する。望遠・低位置という指定だけで正当化しない |

固定の頭身や一つの理想体型を要求しない。自然な脚の重なりや衣服による遮蔽も認めるが、重要な脚の連続・左右・関節位置について矛盾する複数の解釈が残る場合はUNCERTAINとして不採用とする。見えない部位を直接検証したと記さず、実際に見える形と衣服の輪郭から成立を判断できた根拠と観察範囲を残す。画面外への切り落としやぼけで不明点を隠して合格にしない。

1. 全身判定後、主要人物を一人ずつ一時的に切り出し、画像ビューアで頭部・上肢・下肢・接触部を拡大表示する。肩→肘→手首→手、骨盤→左右の股関節→太腿→膝→下腿→足首→足を追い、関節の位置と向きを確認する。腕や指の本数だけで判定しない。
2. 左右それぞれの手について手のひら／甲、親指の側、各指の付け根・本数・曲がりを確認し、左右反転した手、融合・分岐・重複、極端な長さや捻れを調べる。
3. 荷物・道具・衣服・他者と重なる箇所は誰の手足かを特定し、接触と荷重が成立するかを確認する。重要部位の確認不能はPASSにしない。
4. 背景人物も走査し、読み取れる重複・分離した手足・融合を確認する。
5. 全身と縮小表示へ戻り、局所では見落とす比率の崩れ・脚の位置の食い違い・重心の不整合がないことを確認する。この全身再判定を終えてから、文字・本文忠実性・画角・焦点・光の構図評価を行う。

全身判定・局所拡大判定・全身再判定のいずれかがFAIL／UNCERTAINなら不採用とする。人体の不合格を美しい構図で相殺しない。最大3回のfresh生成に含め、不合格画像・過去画像を参照／編集入力にしない。

合格時だけ既存cover-ready.jsonのqa欄へ、実際に拡大確認した人物と部位、左右の手と接触に加え、全身比率・各脚の連続・支持脚／動く脚・重心と接地・短縮と遮蔽の判断、全身再判定を具体的に記す。「人体は自然」「腕が二本」だけでは合格証拠にならない。専用監査JSONや恒久的な検品用画像は増やさない。上限で合格しない画像は配信せず未完了報告へ進む。

## 生成・確認・受け渡し

1200×630のfresh画像を生成し、従来の10項目（NNN、パラシャー名、アリヤー、聖書箇所、本文由来主題句、必要時の補助コピー、誤字、別回混入、本文場面、寸法）を目視確認する。加えて、見る人の立場と選んだカメラ位置が実際の構図に表れ、本文の中心的な行為や緊張が伝わるか、主題へ視線が向くか、距離に応じた自然な鮮明さ・ぼけか、重要な表情・手・人物関係と左側文字を損なっていないか、縮小表示でも主題と文字が伝わるかを確認する。写真表現の評価は場面への適合性で判断し、強いぼけがないことだけで不合格にしない。不合格画像は参照・編集せず、最大3回fresh generationする。

PASS画像だけを`cover-upload.json`の短時間PUT URLへJPEGバイナリとして直接送る。画像バイナリをGitHubやWorkの文字コンテキストへ入れない。R2で1200×630 JPEGと取得可能性を確認し、当該RUNの`cover-ready.json`だけをコミットしてActionsを再起動する。画像監査専用JSONや恒久的なCURRENT RUN IMAGE PACKAGEは作成しない。
